# S-03 云端生词同步 v1

> 更新：2026-09-29
> 状态：`DONE_LOCAL_TEST`（实现、自动测试和真实 PostgreSQL/HTTP 双设备复验完成）
> 契约：`api-contract-v1.3.0`

## 1. 已冻结边界

- 端点：`POST /api/v1/me/words/sync`，一次请求批量推送稳定词条收藏/删除操作，并按签名 cursor 拉取权威变更。
- 只同步审核词表中的稳定 `entryId`（当前格式 `ve-...`）；S-01 导入的纯词面候选继续保留在待解析表中，不冒充稳定词条。
- 请求版本为 `schemaVersion: 1`；每批最多 50 个 operation，每页最多 100 个 change。
- 批次为 `s03-word-batch-v1:<sha256>`，操作为 `s03-word-op-v1:<sha256>`；HTTP `Idempotency-Key` 必须等于 `batchId`。
- revision 使用十进制字符串；设备身份只从已验证服务端会话读取，请求体不能声明设备。
- access/refresh token 仍只保存在内存，离线队列按 `userId` 隔离且不保存凭据。

## 2. 删除和多设备冲突规则

1. 收藏与删除都写入单调 revision；删除不是物理删除，而是可同步的墓碑。
2. 与服务端 revision 相同的显式操作可以收藏、删除或恢复词条。
3. 旧 revision 的删除采用 delete-wins：即使另一设备已有较新收藏，也会生成新的删除 revision。
4. 旧 revision 的收藏不能复活墓碑；客户端必须先拉到最新墓碑 revision，再由用户显式收藏才能恢复。
5. 超前 revision 拒绝且不修改状态；相同 operation/batch 精确重放原结果，相同 ID 携带不同内容返回 `IDEMPOTENCY_KEY_REUSED`。
6. `occurredAt` 只诊断未来超过 5 分钟的设备时间，不参与冲突排序。
7. 新收藏只接受当前已发布内容版本；内容换版后仍允许删除绑定于旧版本的历史收藏，稳定 entry 可在当前 revision 上迁移到新版本。

## 3. 客户端行为

- 正式词卡保存稳定 `entryId`、`pieceId`、`contentVersion`、`vocabKey`、词面和 lemma；旧的纯词面本机记录仍可展示和手动删除。
- 登录、前台、网络恢复、收藏和删除会触发同步；已进入队列的批次不可变，失败以原 batch ID 重放。
- 重试为 1 秒、5 秒、30 秒、2 分钟、10 分钟，之后指数增长并封顶 30 分钟，带最多 20% 抖动。
- 鉴权过期保留队列；终止性协议错误进入最多 20 条本机诊断，避免永久重传。
- 登录前已有词面不会静默上传；需要用户通过 S-01 显式同意导入。远端墓碑会从本机生词本移除对应稳定词条。
- Me 页分别展示学习进度和生词本同步状态；Vocabulary 面板支持逐条删除。

## 4. Quiz 历史冲突口径

- Quiz attempt 是不可变、追加式历史，不使用“最后写入覆盖”。相同 `userId + attemptId` 和相同请求精确重放；相同 ID 携带不同答案稳定拒绝。
- 不同 attempt ID 全部保留，分数只由服务端按版本化题包复算；客户端分数不能覆盖服务端结果。
- 本机报告对同一 piece 只取最新兼容 attempt 做趋势展示；`quiz-score-v1` 排行对每本 work 只计第一次服务端验证 attempt，其余历史仍可查询。
- S-01 可显式导入本机未验证历史并由服务端复判。S-03 不新增可删除/覆盖 Quiz 历史的接口，因此多设备不会互相抹除记录。

## 5. 服务端与数据

- migration `0009_saved_word_sync` 新增权威词条、历史、变更序列、幂等批次和 operation 表。
- `user_saved_words` 保留删除墓碑及最后设备；`user_saved_word_history` 在每次实质变更前归档旧 revision。
- cursor 由用户 ID、change sequence 和服务端 HMAC 绑定，不能跨账户复用或由客户端拼装。
- 每用户每分钟最多 30 个同步请求；写入脱敏审计和 `tingyue_word_sync_batches_total` 指标。
