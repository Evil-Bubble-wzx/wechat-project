# S-04 双设备综合验收

> 日期：2026-10-09
> 状态：`PARTIAL_DEVICE_PENDING`
> 当前事实：本机双会话自动联动通过；真实微信、HTTPS 域名与 Android/iPhone 证据待补

## 1. 范围

S-04 验收 S-01 导入、S-02 进度和 S-03 稳定生词在同一真实账户的两台设备间保持一致，同时确认不同账户隔离。S-04 不扩展支付、实体借阅、收藏和最近访问的同步范围。Quiz 历史日常离线队列及跨设备报告聚合需要单独冻结契约，不能把现有本机报告当作已同步。

## 2. 已完成的本机联动

在隔离 PostgreSQL 18 随机 schema 上运行：

```powershell
cd backend
npm run test:integration:s04-sync
```

脚本启动真实 Fastify HTTP 服务，使用同一账户的两个已验证设备会话和另一个隔离账户，依次验证：

1. 设备 A 写入进度，设备 B 读取相同 revision；
2. 设备 B 用旧 revision 提交听过区间，服务端合并区间并保留 A 的可信断点；
3. 同一进度 mutation 重放只产生一个结果；
4. A 收藏稳定词条，B 拉取；B 删除后，A 拉到删除墓碑；
5. 生词 batch 原 ID 重放保持同一 revision；
6. 另一账户读不到进度或生词；
7. A 退出后旧 token 失效，B 会话仍可读取。

2026-10-09 执行结果：`s04-sync.smoke.passed`。S-01、S-02、S-03 各专项 HTTP/PostgreSQL smoke、客户端 109/109、后端 57/57、契约 5/5 同日通过。测试结束后随机 schema 已清理。
后端 CI 已配置 PostgreSQL 服务并运行 migration、S-01～S-04 联动脚本；真实微信和真机证据仍需单独记录。

## 3. 真机前置条件

- 可用于测试的真实微信小程序账号与两台设备，至少一台 Android、一台 iPhone；
- 已配置 HTTPS API 与资源合法域名，以及目标网络可播放的受控音频；
- 可追踪的测试环境版本、服务端部署版本、契约版本与迁移状态；
- 两个独立测试用户，避免生产用户数据混入；测试内容保持内测权限。

凭据、token、手机号及含个人信息的截图不要提交仓库。测试记录只写匿名用户代号、设备型号、系统版本、网络类型、构建哈希、请求 ID 和结论。

## 4. 真机步骤与完成判定

| 用例 | 操作 | 必须看到 |
| --- | --- | --- |
| D1 同账户登录 | A、B 依次登录同一微信测试账户 | 同一服务端 userId；本机 guest 数据不自动归入账户 |
| D2 进度交替 | A 播放并暂停，B 拉取后继续，A 再拉取 | revision 单调，听过区间并集正确，旧端不覆盖新断点 |
| D3 生词交替 | A 收藏，B 拉取并删除，A 离线后重连 | B 删除墓碑传播；A 的旧保存不复活；显式恢复有效 |
| D4 弱网/重复 | 上传中断、断网重连、重复触发同步 | 队列保留并按原幂等 ID 重试；不重复计数、不丢操作 |
| D5 退出/重装 | A 退出并重装，B 继续使用，A 重新登录 | 旧会话失效；云端权威状态重新拉取；两设备一致 |
| D6 账户隔离 | A 切换到另一测试账户 | 不出现上一账户的进度、词条或离线队列 |
| D7 音频系统事件 | 后台、锁屏、系统暂停/恢复 | X-02 可信时长与断点符合真机验收表 |

每项保存 Android 与 iPhone 的版本、时间、操作结果和匿名化证据。全部通过且缺陷关闭后，才把 S-04 改为 `DONE`；本机自动脚本只支持 `PARTIAL_DEVICE_PENDING`。
