1. 当前工作区代码、自动测试、构建产物和真实联调证据；

## 8. 文档维护规则

1. 新状态先更新专项证据，再更新实施计划、短版进度和 v3.0 总览。
2. 平行分支成果必须写明分支、完整 SHA、验证日期和“是否已进入当前工作区”。
3. 历史记录保留原结论；如需修正，只追加勘误或链接更新日期。
4. 模板必须标明“未填写/未签署”，不能算作验收证据。
5. 删除或替换执行基线时，同步修复索引和所有活跃引用。
6. 文档中的测试数字必须来自实际命令结果；失败项不得用分支自报数字覆盖。
