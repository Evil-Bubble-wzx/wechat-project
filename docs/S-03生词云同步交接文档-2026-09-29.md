### 2.1 API 与批次

- 端点：`POST /api/v1/me/words/sync`；
- 单请求同时推送稳定生词 operation，并按签名 cursor 拉取权威 change；
- 请求 `schemaVersion: 1`；
- 每批最多 50 个 operation，每页 `limit` 为 1～100；
- 批次 ID：`s03-word-batch-v1:<sha256>`；
- operation ID：`s03-word-op-v1:<sha256>`；
- `Idempotency-Key` 必须等于 `batchId`；
- revision 使用十进制字符串；
- 设备身份只从已验证服务端 session 获取，请求体不能声明设备。

### 2.2 稳定词条与版本

- 只同步审核词表中的稳定 `entryId`，当前格式为 `ve-...`；
- operation 同时携带 `entryId`、`pieceId`、`contentVersion`、`vocabKey`、surface 和 lemma；
- 服务端校验 stable entry identity 的一致性；
- 新收藏只接受当前已发布内容版本；
- 历史收藏仍可删除；当前 revision 的显式 save 可以把稳定 entry 迁移到新内容版本；
- S-01 的 surface-only candidate 继续留在待解析表，不自动冒充稳定词条。

### 2.3 删除与多设备规则

1. 收藏和删除都生成单调 revision；删除保存为同步墓碑，不物理删除。
2. 基于当前 revision 的 save/delete/restore 正常生效。
3. stale delete 使用 delete-wins，会生成新的删除 revision。
4. stale save 不能复活墓碑；用户必须先拉取最新 tombstone revision，再显式 save。
5. future revision 拒绝且不修改状态。
6. 相同 batch/operation 同载荷精确重放；同 ID 不同载荷返回 `IDEMPOTENCY_KEY_REUSED`。
7. `occurredAt` 只诊断未来超过 5 分钟的设备时钟，不参与排序。

### 2.4 客户端行为

- 登录、回前台、网络恢复、收藏和删除触发同步；
- 队列按 `userId` 隔离，不保存 access/refresh token；
- 已入队 batch 不可变，失败使用原 batch ID 重放；
- 重试节奏为 1 秒、5 秒、30 秒、2 分钟、10 分钟，之后指数增长并封顶 30 分钟，最多 20% 抖动；
- 鉴权过期保留队列；终止性协议错误最多保留 20 条本机诊断；
- 登录前纯词面不会静默上传，仍需 S-01 显式导入；
- 远端墓碑会从本机生词本移除对应稳定词条；
- Me 页展示生词同步汇总状态；Vocabulary 面板支持稳定词条逐项删除，旧纯词面仍可展示和手动删除。

## 3. 来源分支数据模型

`0009_saved_word_sync` 新增：

- `user_saved_words`：用户稳定词条、revision、墓碑、服务端更新时间、最后设备和 change sequence；
- `user_saved_word_history`：每次实质变更前归档旧 revision；
- `word_sync_batches`：批次幂等状态和响应；
- `word_sync_operations`：跨批 operation 幂等响应；
- 全局 change sequence 和按用户/change sequence 的读取索引。

当前实现的用户状态主键为 `(user_id, entry_id)`，piece/version/vocabKey 作为稳定身份校验及版本迁移字段。业务限流为每用户每分钟 30 个同步请求；指标为 `tingyue_word_sync_batches_total`。审计只记录计数、结果和分页状态，不记录词面或释义。
