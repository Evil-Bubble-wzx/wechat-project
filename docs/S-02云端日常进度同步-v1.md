# S-02 云端日常进度同步 v1

> 日期：2026-09-29
> 契约：`api-contract-v1.2.0`
> 当前状态：`DONE_LOCAL_TEST`；代码、自动验收、隔离 PostgreSQL migration 和真实 HTTP 链路均已通过

## 1. 范围与权威边界

S-02 只同步篇章播放进度。生词、Quiz、收藏和最近访问不属于本任务。登录账户以服务端合并结果为权威状态；本机负责离线体验、可信播放证据和待确认 overlay，不上传或自证覆盖率、完成状态、累计时长和资源时长。

游客与每个 `userId` 使用独立本机学习空间。登录不会自动把 guest 数据归入账号；登录前历史仍通过 S-01 的显式同意流程导入。退出会停止发送并切回 guest，同一账号重新登录后恢复它自己的队列。

## 2. 冻结契约

- `PUT /api/v1/me/progress/{pieceId}`：提交单篇完整证据快照；
- `GET /api/v1/me/progress/{pieceId}`：读取当前发布版本的单篇权威状态；
- `GET /api/v1/me/progress`：按稳定 cursor 分页读取当前版本进度，默认 50、最大 100；
- 服务端响应 `X-API-Contract-Version`；客户端必须观察到兼容的 1.2+ 服务端版本后才启用队列；
- 写请求只允许 `schemaVersion`、`mutationId`、`baseRevision`、`contentVersion`、`checkpointMs` 和 `listenedRangesMs`；
- `Idempotency-Key` 必须等于 `mutationId`；`userId + mutationId` 回执保留 30 天；同键不同载荷稳定拒绝；
- revision 是每个 `userId + pieceId + contentVersion` 独立递增的 `bigint`，JSON 中使用十进制字符串；
- 单请求最多 500 个规范区间、64 KiB；正常写入限流为每用户每分钟 30 次。

## 3. 合并规则

1. 同一内容版本的听过区间始终取并集，并按服务端音频时长校验和复算；客户端派生字段不进入请求。
2. `baseRevision` 等于当前 revision 时，本次可信断点生效。
3. 旧 revision 的迟到请求仍贡献听过区间，但不能覆盖当前断点；响应为 `merged_stale_base` 且 `checkpointAccepted:false`。
4. 同版本完成状态单调，只能从未完成变为完成；完成要求覆盖率至少 90% 且尾部 3 秒存在可信证据。
5. 内容版本分别保存。已知且未撤销的旧正式版本只进入历史，不影响当前版本；未知、撤销或不可访问版本永久拒绝。
6. 设备时钟、客户端 duration、coverage、listenedMs、completed 和设备标识均不作为服务端事实。
7. S-01 已有进度在 migration 0008 中初始化为 revision 1；后续 S-01 导入按同内容版本合并并递增 revision。

## 4. 客户端队列

- 播放器本机进度与 outbox 在同一次同步存储写入中更新；网络发送异步执行；
- 每个账号、篇章和内容版本只保留一个尚未发送的最新快照；在途请求保持不可变，新证据形成下一 mutation；
- 连续播放约每 30 秒尝试同步；暂停、自然结束、切篇和应用退后台立即落队；
- 网络、超时、429、502、503、504 使用稳定 mutationId 和指数退避，最长 5 分钟；恢复前台和“立即重试”可提前唤醒；
- 退出立即停发；同账号重新登录恢复；永久错误停止自动请求并保留脱敏 requestId；
- 云端状态是持久化基线，未确认队列仅作为本机 overlay。迟到 mutation 已确认后不得自动用新 revision 重放旧断点；
- 设置页只展示“已同步 / 待同步 / 部分失败”和手动重试，正常同步不打断播放。

## 5. 数据库与可观测性

`0008_daily_progress_sync` 将 `user_learning_progress` 主键扩展为 `(user_id, piece_id, content_version)`，增加 revision、服务端更新时间、最后 mutation 和历史标记，并新增 30 天回执表 `progress_sync_mutations`。

审计只记录 mergeStatus、revision、区间数量和是否历史版本；不记录 token、明文身份或具体区间。Prometheus 增加 `tingyue_progress_sync_total`，HTTP 通用指标继续覆盖失败码与延迟。
