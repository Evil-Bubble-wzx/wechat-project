## 1. 已冻结边界

- 端点：`POST /api/v1/me/progress/sync`，一次请求同时批量推送本机证据并按签名 cursor 拉取权威进度。
- 请求版本：`schemaVersion: 1`；每批最多 50 个 operation，每页最多 100 个 change。
- 幂等：批次为 `s02-batch-v1:<sha256>`，操作为 `s02-op-v1:<sha256>`；HTTP `Idempotency-Key` 必须等于 `batchId`。
- 修订号以十进制字符串传输，避免小程序 JavaScript 整数精度问题。
- 设备身份来自服务端会话表中的 `device_id`，请求体不能声明或替换设备身份。
- 只接受当前已发布内容版本和服务端音频时长；换版后客户端以 `baseRevision: "0"` 建立新状态，旧版本证据终止处理。

## 2. 多设备合并规则

1. 收听区间始终规范化后取并集，50ms 内相邻区间合并。
2. `baseRevision` 等于服务端 revision 时，可以接受新的可信断点。
3. `baseRevision` 落后时，只合并区间和自然结束证据，保留服务端已有断点。
4. `baseRevision` 超前时拒绝且不修改状态。
5. 完成必须同时满足：观察到自然结束、唯一覆盖率至少 90%、末 3 秒已覆盖。
6. `occurredAt` 只用于时钟诊断；比服务端未来超过 5 分钟返回 `future_skew`，不参与冲突排序。
7. revision 只在状态发生实质变化时增加；服务端写入独立 change sequence 供签名 cursor 拉取。

## 3. 服务端实现

- migration `0008_progress_sync`：扩展 `user_learning_progress` 的 revision、自然结束、服务端时间、设备来源和 change sequence。
- 新增历史表、批次表和操作表，支持内容换版留档、批次精确重放和跨批 operation 去重。
- S-01 与 S-02 共用区间和完成事实计算；S-01 保持既有一次性导入兼容边界。
- 同一用户/篇目在事务内锁定；批次和操作 ID 相同但请求内容不同返回 `IDEMPOTENCY_KEY_REUSED`。
- 每用户每分钟最多 30 个同步请求；写入脱敏审计和 `tingyue_progress_sync_batches_total` 指标。

## 4. 小程序实现

- 每个 `userId` 使用独立持久化队列；队列不保存 access/refresh token。
- 登录激活时把现有本机进度作为游客基线，基线以前的数据不会自动进入 S-02；游客历史继续只通过 S-01 显式同意导入。
- 播放器每次可信持久化向同步管理器提交证据；登录、前台、网络恢复、播放暂停/结束触发同步，播放中最长约 15 秒形成一次批次。
- 草稿可合并，进入队列的批次不可变；失败用同一个 batch ID 重放。
- 重试序列为 1 秒、5 秒、30 秒、2 分钟、10 分钟，之后指数增长并封顶 30 分钟，带最多 20% 抖动。
- 鉴权过期保留队列等待重新登录；终止性协议错误最多保存 20 条本机诊断。
- 拉到远端状态时更新持久化进度，但不 seek 或打断正在播放的会话；旧活动会话也不能倒退更新的远端断点。
- Me 页展示正在同步、待处理、已同步或稍后重试状态。
