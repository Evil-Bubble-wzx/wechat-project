# 正式版前后端功能对齐清单

更新：2026-10-10。目标：对齐所有前后端功能。用户补充：“现在就在开发正式版啊”。本清单覆盖当前正式版完整业务闭环，Demo 的本机演示不作为正式业务完成证据。

## 完成条件

每项必须同时具有服务端数据模型与契约、真实页面调用、账号与内容版本隔离、失败恢复，以及对应范围的自动或真实依赖验收。播放暂停、倍速等设备控制保留客户端执行，不为按钮强行增加服务端接口。新增书目应可由后台发布后在前端发现并加载完整音频、字幕、词卡与题包，不依赖重新打包写死书目。

本机通过与微信真机、生产部署分开记录。未授权部署、生产迁移或 GitHub 推送；生产凭据、合法域名、内容权利及真机验收门槛不因功能开发而关闭。

## Quiz 云历史和学习统计口径

Quiz 答案先持久化到发起账号的不可变队列。网络恢复、前台返回和手动重试不改变答案、版本或时间；不完整确认保留队列，存储失败阻止提交，损坏队列不会被静默覆盖。退出和换账号忽略迟到的提交、历史与摘要回执，不自动导入游客结果。

GET /api/v1/me/quiz-history 按账号返回数字 revision 增量，包含拒绝及撤回状态；签名游标绑定账号和派生序列 epoch。失效游标完整重拉成功后才替换旧缓存，部分失败保留原缓存。0014 回退只移除派生同步列，保留全部 attempt 和逐题答案，再升级会使旧游标失效。

GET /api/v1/me/learning-summary 同时供 Me 和报告使用。完成数量是篇章，不冒充整书；词数取首次完成时的内容版本，缺少词数时总数为 null，另保留已知词数。有效听读采用各逻辑篇章跨版本的最大确认覆盖时长，不重复累计播放区间，也不等于含重复播放的本机计时。Quiz 平均正确率和满六篇趋势只采用最新的服务端验真、未撤回、当前版本仍兼容的不同篇章，按实际服务端验真时刻排序。大整数保持字符串，失败显示上次缓存及更新时间。进度区间仍来自客户端上报并由服务端验证/合并，不等于反作弊验收已通过。

本机练习答案和反馈仍保留；游客与 Demo 使用本机口径。登录正式版没有云摘要时显示待同步，不用本机练习分数代替。历史兼容标记是该页拉取时快照，报告平均及趋势以最新摘要为准。

## 排行详情统计与查询

从榜单点击匿名参与者，跳转至独立 Quizzes 页。页面固定列表的 snapshotId、校区、期间、年级和级别；搜索和排序只影响记录列表，不改变整个期间的统计或积分。返回时保留原筛选，其他账号不能复用该返回上下文。

PASSED 和 ALL 均按期间内每篇章最新服务端验真、未撤回的结果去重；PASSED 再按保存的 mastery 判定，不写死 80% 门槛。Total Chapters 是篇章数，不冒充完成整书数；列表保留每次验真记录及其本次新增答题积分。期间与排序采用服务端 verified_at，不采信客户端提交时间。

每组满 6 篇不同章节后，按验真时间取最早 3 篇和最近 3 篇计算正确率趋势。趋势组中任一阅读级别未知，组级别为 null；平均级别和 Fiction 仅用已知项，并由 API 返回样本数。任一章节词数未知，总词数为 null；其他未知项显示 —。榜单主指标仍为 learning-points-v2，总积分包括听读、首次完成与首次答对，不伪造 PASSED/ALL 积分拆分。

服务端支持标题、系列、作者、作品及章节编号的文字搜索；%、_ 按普通字符处理。Date、Title、Correct、Level、Words、Quiz Points 共 6 个字段可升序/降序，未知值最后；分页游标绑定整个查询范围，换筛选、排序、快照或参与者后不得复用。只输出匿名展示字段，不返回账号 ID、联系方式或逐题答案。

0015 只添加不可变快照分析字段，旧 /quizzes 契约继续保留。缺少新统计的旧快照不猜测补值；榜单刷新重建新的快照身份，固定旧快照的分析请求提示刷新。回退 0015 会移除派生统计，但不删除答案、积分或学习事件；再升级后必须重建分析，应用时间完整精度参与来源指纹，避免复用缺失统计的旧快照。标题、作者和系列等查询字段也参与指纹，元数据变更重建不会覆写旧快照。

排行专项以实际前端模块、真实 HTTP/Fastify/隔离 PostgreSQL 与 Edge 验证。微信身份是测试夹具，导航使用预览桥，不代表微信真机验收。运行后端 test:integration:ranking-browser 需要先构建正式产物、本机隔离数据库和 Edge；结果及截图见 [排行浏览器记录](../artifacts/production/ranking-detail-test.json) 与 [手机布局](../artifacts/production/ranking-detail-mobile.png)。

## 签名音频续签与播放恢复

暂停后再次播放若链接接近过期，或原生音频报错，播放器重新请求同篇章、同内容版本的清单。七资源摘要、Quiz 版本、测量时长、音频资产 ID、字节摘要、大小和 MIME 必须一致，且发起账号与当前账号一致；版本或权限变化时停止恢复并要求重新打开章节。沿用已有 manifest 接口，未新增契约字段或迁移。

每次明确播放至多自动续签一次，再失败显示可手动重试提示，不进行无限重试。续签只更换资源链接，不重复下载字幕/词卡/题包，不把等待时间或拖动跳过的区间计入学习。保留当前位置、可信断点、已听区间、速度和循环；续签期间用户暂停或系统停止后不自动播放，用户拖动采用新目标。切章、换账号或页面获得更新的已验真资源时丢弃旧回复。普通链接更新不打断正在播放的旧流。

catalog-ingestion smoke 使用隔离 PG、真实 MinIO/BullMQ/ffprobe 与前端续签模块，验证真实过期预签名返回 403、续签后 Range 206 和完整音频 SHA-256，以及换版/受限拒绝。audio-lease-browser-check 使用本机 HTTP 403/206 夹具、测试 manifest 适配器和实际 Edge/前端播放器，验证 30 秒断点恢复与真实解码波形；记录见 [音频续签回归产物](../artifacts/production/audio-lease-test.json)。两项证据相互补充，不等于微信真机、腾讯云或生产 CDN 已通过。已有签名 URL 不等于即时撤权，续签时服务端重新检查当前版本与权限。

## 已复现的回归问题

1. 已修复：导入请求 A 的迟到成功或失败回执不再改变 B 的状态；只合并发起账号的最新数据。
2. 已修复：同版本签名更新不重置断点，过期或原生音频错误可续签恢复；暂停、拖动、切章、换账号及更新链接的迟到响应已隔离。音频报错后归零不覆盖断点；旧账号的迟到播放事件不写入新账号。预览桥接忽略已取消或被新来源替代的旧播放请求错误。
3. 已修复：最近七日查询不再直接接受截至 2026-09-20 的旧快照；当前窗口刷新、缓存复用、8 路并发和列表/详情同快照已验证。
4. 已修复：排行个人名次、选项和详情的迟到回复绑定发起账号，切换至 B 后不应用 A 的响应。
5. 已修复：收藏与生词的 change_seq 转成文本输出后，ORDER BY 曾误按文本别名排序，序号到 10 时漏记录。改为底层数字列排序，并按账号串行提交，分页测试覆盖该边界。
6. 已修复：相同游标下新拉取不再复用之前的空结果；失败重试仍使用原批次。生词的旧保存确认不能覆盖用户新删除，旧 revision 不回退，不完整确认保留原待同步批次。

7. 已修复：检索不再清空其他书目的缓存；未知章节不回退第一章；远程章节先验证资源再选音频，云端断点先拉取，旧版本播放状态不能覆写新页面。
8. 已修复：七种资源并发完成时先锁批次再检查剩余项，避免最后几个任务彼此不可见而漏组装；回滚恢复章节统计投影和首章书目字段。词库引用、字幕时长和题数在发布前校验。
