# 听阅独立运营网页

用户已选择“独立运营网页（推荐）”。当前已接通本地内容包上传、批次浏览、处理重试、取消清理和结果查询。它不是已上线的运营后台，也不包含正式网页登录。

## 已实现

- 每批对应已有作品、章节和内容版本的七类资源。最多 8 MiB 切片计算完整 SHA-256，不将大文件整体载入内存。
- 分片直传、暂停、账号草稿、重新选择原文件、刷新和过期续传。按完整摘要匹配，以真实存储分片为准。
- 先保存不可变合并记录，新会话使用独立对象身份。合并后数据库确认失败按原记录恢复，Worker 再校验完整摘要；旧会话异常不猜测成功。
- 按状态、作品和章节 ID 浏览批次，服务端倒序分页，游标绑定账号及筛选，保留微秒精度。列表为当前读取状态，不是不可变统计快照。
- 查看原因和累计次数，明确点击重试。意图、代次和审计原子保存，入队失败可按同一请求恢复；刷新保留待确认操作，不重置次数或删除原失败队列记录。
- 明确确认后取消未执行任务和未完成分片。正在执行或完成的批次不可取消；确认绑定当前批次，切换后重新确认。完整文件与审核事实保留。
- 取消先持久化，清理失败继续原请求；Abort 后查询分片，确认后才标记清理完成。S3 在途上传可能需再次清理，生产并发取消仍须实际厂商验收。[Amazon S3 取消规则](https://docs.aws.amazon.com/AmazonS3/latest/API/API_AbortMultipartUpload.html)
- 明确提交处理才启动校验，处理完成仍需审核。页面不审批、发布或授予角色。
- 凭证仅内存；草稿不保存文件、ETag 或临时 URL。操作时锁定目标，断开或关闭停止本页操作，迟到响应不跨账号写回；断开不撤销服务器会话。

## 本地运行

在 backend 使用已迁移的同一套本地数据库、Redis 和对象存储运行 start:api、start:worker，默认入口为 http://127.0.0.1:3100/operations/。

页面仅 APP_ENV=local/test 注册。用已有授权的本地管理员会话连接，不创建角色；content_admin 与 operations_admin 可访问，普通账户拒绝。生产网页登录、受控授权、HTTPS、域名与 CORS/CSP 待接入，不能公开本地凭证输入页。

当前 api-contract-v2.9.0，19 条迁移、46 个关系。0017/0018/0019 有恢复、运营或整组事实时拒绝回退，先备份并制定恢复方案，不删除事实强行降级。

## 自动验收

显式配置本机 15432 测试库、MinIO、Redis 和 ffprobe，在 backend 运行：

- npm run test:integration:operations-browser：约 9.6 MB 原 VTT 双分片、刷新/过期续传、错误文件和合并后故障。
- npm run test:integration:ingestion-operations：真实 HTTP/PG/BullMQ/MinIO 的分页、账号/筛选游标、等锁撤权、重试/审计、入队故障、取消清理及旧代次拒绝。
- npm run test:integration:operations-control-browser：实际 Edge 的 20+20+16 分页、筛选、原因/次数、重试与取消确认；刷新恢复只有一个重试意图，累计次数 1→2；375/768/1280px 通过。

夹具实际启动并终止独立 Worker：活跃锁阻止误接管，终止后保留旧 active 记录并重建丢失队列，新代次校验成功，旧回执不改状态。使用随机 schema、队列和对象，仅清理自身数据，不触碰生产、真实角色或批准。

## 文件夹整组导入

2.9 整组导入已本机通过：显式清单和文件夹绑定，原子创建草稿作品/章节与批次，已有属性冲突整组回滚；IndexedDB 保存账号清单和原重试键，不保存文件或凭证。实际 HTTP/PG/MinIO/BullMQ/Edge 通过 2 部作品、20 章、140 个资源声明（45 个独立文件）、创建响应丢失恢复、中断续传、错误文件拒绝和三宽度。所有章节仅到待审核，零真实批准/发布。生产网页登录、受控授权、独立书目编辑/审批页面、数百独立文件/GB 压测、云环境故障矩阵及真机仍待完成。

1. 准备 JSON 清单，点“查看清单格式”读取模板。填写来源、版本、作品/章节 ID、标题、权限和明确顺序；description 未知填 null。每章 items 按 assetType 与 relativePath 显式指定七文件，相对路径从所选素材根文件夹内部开始。metadata/quiz 的身份与内容版本须相同。
2. 连接已有授权管理员会话，选择清单和素材根文件夹，点击“校验清单与所有文件”。系统核对路径、身份、大小和完整摘要，没有通过不会创建目录；额外文件不猜测绑定。
3. 勾选确认后点“创建整组导入”。已存在的目录属性须完全一致；任何冲突整组回滚。取消过的章节版本也不重新复用，修改资源用新 contentVersion。
4. 点击“上传整组 / 继续上传”。上传成功后显式点“提交整组处理”，再刷新状态；有失败章打开“章节详情”，沿用已有重试和取消流程。提交处理不是版权或发布批准。
5. 中断后读取组 ID 或“恢复本机整组草稿”，重新选择原文件夹并校验。创建响应丢失重放原键恢复同一组；完成的文件不重传。页面不自动上传或处理。最近列表只展示 20 组，旧组可凭 ID 读取。

在 backend 运行 test:integration:bulk-import 与 test:integration:bulk-import-browser。实际夹具为 2 书、20 章、140 个资源声明，45 个独立文件复用于章节；零真实审核或发布，不是 140 个独立文件/GB 压测。结果见 [整组浏览器验收](../artifacts/production/bulk-import-test.json) 与 [整组桌面](../artifacts/production/bulk-import-desktop.png)。本地临时文件夹、随机 schema/队列和专属对象前缀仅用于测试。
