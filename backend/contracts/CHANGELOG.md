# API contract changelog

## api-contract-v2.9.0 - 2026-10-12

- 新增整组导入创建、按 ID 读取和最近 20 组列表，支持明确多作品、多章节与相对路径清单。0019 保存账号幂等和有序批次引用；草稿目录、全部批次和审计原子提交，已有属性冲突整组回滚。
- 浏览器文件夹预检、8 MiB 增量 SHA-256、IndexedDB 账号草稿、原键恢复、整组分片上传及显式提交处理。创建响应丢失和上传中断可恢复；文件、凭证、ETag 和预签名 URL 不持久化。
- 导入不覆盖已有目录或复用旧章节版本；单章入口共享章节锁、重查 active 管理员并保护旧版本事实。合法同键原声明仍可重放；错误 JSON/大小返回稳定 INVALID_REQUEST。
- 本机真实 HTTP/PG/MinIO/BullMQ/Edge 通过 2 书、20 章、140 个资源声明（45 个独立文件）和冲突/撤权/回退保护，待审核而非自动发布；生产登录、独立书目编辑/审批和 GB 级容量仍待实现或验收。

## api-contract-v2.8.0 - 2026-10-12

- 增加管理批次列表和任务详情，账号/筛选游标保留创建时间微秒；恢复响应新增尝试次数、取消资格、待清理数和内容状态。
- 0018 保存运营幂等记录、执行代次和清理确认。重试/取消意图与审计原子提交，同键不重置次数或重复新意图；入队和清理失败按原请求恢复，旧失败队列保留。
- Worker 按批次锁检查代次，未取得处理锁不记虚假失败，计数按事实重算；恢复检查真实处理锁，旧 active 记录不作为仍活着的证明，忽略旧代次，次数耗尽不再入队。取消拒绝运行/完成批次，完整文件保留。旧 retry/cancel 仍接受无请求体或空对象，未知字段拒绝。
- 独立网页的分页、筛选、原因/次数、重试、取消和待审核状态已实际 HTTP/PG/BullMQ/MinIO/Edge 验收，包括等锁撤权、入队/清理故障及 Worker 实际终止接管。无真实批准或部署。

## api-contract-v2.7.0 - 2026-10-12

- 增加管理员 operations-context、批次 recovery、上传会话状态查询及 renew。续签读取真实对象存储分片，返回缺失分片 URL；续期幂等绑定服务端管理员和请求，URL 不持久化。原有微信阅读接口保持兼容。
- 0017 增加上传对象标识、不可变合并意图和上传变更幂等记录。新会话使用唯一对象路径；完成请求验证真实分片编号、大小和 ETag，先提交确认意图再合并，合并后确认失败可核对对象身份恢复。完整 SHA-256 仍由 Worker 验真；旧会话无标识的异常恢复不猜测成功。
- 独立运营网页在 local/test 提供选包、增量摘要、分片上传、暂停、刷新恢复、显式提交处理与结果读取。凭证只在内存，页面不授予角色或审核发布；dev/prod 不提供联调页面。生产网页登录、多章节批量、取消/死信和规模仍待完成。

## api-contract-v2.6.0 - 2026-10-12

- 原始 UTF-8 VTT/SRT 可通过已有分片上传和 Worker 自动转换为阅读 JSON；输入上限 100 MiB，输出维持 8 MiB。逐行处理、行/cue 上限、UTF-8/时间轴/标识校验，不修复、重排或跳过错误。既有规范 JSON 和全部阅读接口不变，无新增迁移。
- incoming 保留原始字节及声明摘要；original→ready 父子关系和验证记录保存转换版本、原始摘要/大小/MIME 与忽略的呈现组件。content_assets、manifest 和发布资源按派生文件实际字节计算摘要、大小及 MIME。
- 单轨旁白转换不执行样式，不推测翻译或上下文词义；复杂标记、外部时钟映射等需明确规范化。原始字幕输出 tokens:[]，有审核映射的 JSON 继续保留点词能力；转换不代替审核或开放发布门槛。
- 实际管理 HTTP→MinIO→BullMQ/Worker→PG→前端通过 JSON/SRT/VTT 三版本、超过 8 MiB 的原始 VTT、原始与派生摘要、并发、错误摘要/重叠/超时长拒绝和回滚。Edge 完成 SRT/VTT 书库→详情→播放器、字幕与句切换及三宽度；微信身份、导航与 CORS 为测试桥，不能算生产或真机证据。
- 浏览器预览补齐 wx.request 的真实 fetch/二进制/超时/取消桥；测试路由收尾等待在途请求且不输出鉴权头。运营上传页面、续传/取消/死信全链路和数百文件/GB 压测仍待完成。

## api-contract-v2.5.0 - 2026-10-12

- 新增 GET /api/v1/me/student-profile、GET /api/v1/admin/student-profile-options、GET/PUT /api/v1/admin/student-profiles/{studentCode}。本人只读；管理端仅 active operations_admin，content_admin 和学生无权访问。客户端观察到 2.5 后启用，既有 CurrentUser 和登录响应不变。
- 管理写入必须提供原 revision、稳定 mutationId/Idempotency-Key、校区/年级/级别及变更依据；来源和核验时间由服务器生成，不接受身份 UUID 或回溯生效时间。无校区时年级/级别为空，禁止选择失效校区。
- 同账号/目标有序锁及角色二次锁定检查，revision 冲突拒绝覆盖，幂等结果加密并与目标和载荷绑定，变更/版本/审计原子提交。页面失败只显式重试同一内存请求，返回前台核验权限和读取最新档案，不建立自动离线管理员写队列。
- 用户确认“维持期初档案分组，下个榜单周期才生效”。周/月/年继续按期间起点，滚动七日需窗口起点越过变更时间；不改 learning-points-v2 算法或撤销累计积分。现有聚合与 Worker 逻辑保留，新增转校回归。
- 0016 新增查询码和 revision 派生字段，不新增关系；回退保留档案、版本、学习事实、幂等和审计，再升级产生新查询码，旧码绑定请求不可重放。实际页面/HTTP/Fastify/隔离 PG/Edge 已通过权限、并发、撤权、保存、期初分组和回退测试；学校批量同步、真实运营授权、真机和生产仍待完成。

## api-contract-v2.4.0 - 2026-10-10

- 新增 GET /api/v1/rankings/{participantId}/quiz-analysis，必须指定列表快照；旧 /quizzes 保持兼容。新增 Schema 与实际响应示例，客户端以观察到的 2.4 能力启用独立 Quizzes 页面。
- PASSED/ALL 按期间内每篇章最新验真且未撤回的记录去重，PASSED 采用保存的 mastery。篇章不冒充整书；未知词数保持 null，级别/分类返回已知样本数；六篇后计算最早/最近各三篇趋势，缺少组级别则 null。总学习积分与通过状态分开，不改 learning-points-v2 计分规则。
- 日期与期间采用服务端 verified_at；列表保留逐次记录和本次新增答题积分。服务端全量文字搜索支持标题/系列/作者/编号，转义 %/_；六字段升降序与 NULL 最后，签名游标绑定完整查询范围。
- 0015 添加不可变快照分析字段与索引，不补写旧快照。回退保留原始答案、积分和事件，再升级重新构建；来源指纹含迁移应用时间完整精度及查询元数据，避免复用缺失统计或旧标题/作者的快照。
- 实际前端/HTTP/Fastify/隔离 PostgreSQL/Edge 已通过 50+8 分页、统计、搜索/排序、隐私、范围游标、元数据更新、回退重建及返回筛选。微信身份为本地测试夹具，不代表真机或生产发布。

## api-contract-v2.2.0 - 2026-10-10

- works/work/manifest 增加可选规范化 metadata 和音频 durationMs；未知元数据为 null，不借用固定 Peter 字段。目录只返回含当前已发布章节的已发布书目。
- works 支持 query 与 category（all、fiction、nonfiction、available），搜索标题、系列、作者和编号；游标绑定筛选。available 指有免费已发布章节可阅读，不代表实体库存。
- 0013 保存内容版本元数据和处理验证结果；音频时长由 ffprobe 测量，题包和有序题目由同版本导入生成。发布、回滚同步更新章节和书目投影；有验证数据时拒绝回退迁移。
- 前端在观察到 2.2 后启用动态书库；完整资源验证身份、版本、清单摘要、JSON 字节数与 SHA-256 后使用，不混入本地旧字幕、词卡或题包。下架/受限回执清除旧题包，网络错误保留可重试状态。
- 阅读资源目前要求每份不超过 8 MiB 的规范化 JSON；Quiz 最多 100 题，与提交接口一致。VTT/SRT 自动规范化、批量运营界面、规模和真机验证仍待完成。

## api-contract-v2.1.0 - 2026-10-10

- 排行列表和详情增加可选 `snapshotId`，详情查询可指定列表快照；游标与筛选必须匹配同一快照。
- 最近七天按服务端时间建立最长 30 秒缓存的 168 小时窗口；即使没有学习事件也会淘汰过期数据。周、月、年仍使用严格期间。
- 新增 `POST /api/v1/me/library/sync`，同步账号级收藏、取消收藏墓碑和最近打开时间。打开行为不计入学习时长或积分。
- 批次与操作均可幂等重放；每次新拉取需新 batchId，重试则保留原批次。游标绑定账号，取消收藏优先于旧设备的迟到收藏。
- 新增迁移 `0012_reader_library`，有账户数据时拒绝破坏性回滚。仅完成本机真实 HTTP/数据库验收，不代表已部署生产或通过微信真机验收。
- S-03 请求增加可选 `pullNonce`：新拉取使用新值，重试保留原值，旧客户端可省略。生词与收藏变更按数字序号排序，并按账号串行提交，避免序号到 10 或空结果幂等重放时漏掉另一设备的新记录。
- 生词客户端保留新删除意图、拒绝旧 revision 回退；不完整服务端确认保留原不可变批次，供显式重试，不丢弃未确认操作。

## api-contract-v2.0.0 - 2026-10-09

- 排行规则改为 `learning-points-v2`：新增有效听读每满 1 秒加 1 分，每篇首次完成加 50 分，每篇同一逻辑题首次经服务端确认答对加 10 分。重复证据不重复计分，不设业务积分上限。
- 破坏性变更：`rankingScore` 及积分明细由数字改为十进制整数字符串；旧六项加权拆解改为听读、完成、答题三项。前后端需按同一契约发布。
- 排行配置新增积分规则并返回 `scoreCap: null`；最近 7 日、周、月、年榜按期间新增积分排序，个人累计积分不受榜单筛选影响。
- 新增 `GET /api/v1/me/learning-score`；进度和 Quiz 响应可携带 `learningScore`。路径仍沿用 `/api/v1`，Schema 文件名保持 `api-v1.schema.json`。
- 迁移 `0010_learning_points` 保留旧规则快照并回填历史积分；`0011_learning_score_consistency` 补齐账号级串行化、Quiz 撤回与恢复的期间重建任务。历史回填不能还原逐秒发生日期，回滚有防丢数据拒绝条件。
- 2026-10-10 已通过本机契约、数据库、HTTP 与浏览器回归；生产部署和微信真机验收仍待完成。规则详见 [ADR 0004](../docs/adr/0004-learning-points-v2.md)。

## api-contract-v1.2.0 - 2026-09-29

- 新增 `GET /api/v1/me/progress`、`GET /api/v1/me/progress/{pieceId}` 和 `PUT /api/v1/me/progress/{pieceId}`。
- 进度写入以 `userId + mutationId` 幂等；服务端 revision 为字符串形式的单调 `bigint`。

- API 响应增加 `X-API-Contract-Version`；客户端只有观察到服务端版本至少为 1.2 时才启用 S-02。
