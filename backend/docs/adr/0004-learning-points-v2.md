# 累计学习积分与期间排行

日期：2026-10-10。状态：已实现并通过本机验证；生产及微信真机待验收。规则版本：`learning-points-v2`。接口契约：`api-contract-v2.0.0`。

## 需求与决策

用户要求：“排行算法进行更新 每学习一部分增加一部分分数 分数不做上上限 做前后端功能对齐”。

采用逐项累计学习积分，替换旧 `quiz-score-v1` 的有上限加权算法。默认系数为新增有效听读整秒 1 分、每篇首次完成 50 分、每篇同一逻辑题首次确认答对 10 分。这些系数是实现采用的默认值，不是用户指定值；后续调整应发布新规则版本，不静默改写历史积分和快照。

## 计分规则

累计积分 = 已计分有效听读秒数 × 1 + 首次完成篇数 × 50 + 首次确认答对题数 × 10。

- 有效听读按服务端校验后的区间累计，以整秒计分；不足 1 秒的部分留待后续累计。重复听已计分部分、重复 mutation 或重复导入不重复得分。
- 首次完成以服务端计算的完成状态为准，每篇只奖励一次，不接受客户端完成声明。
- 正确答案按用户、篇目和逻辑题目去重。此前答错的题后来首次答对可补分，重复答对不补分。Quiz 仍在完整答卷提交并验证后计分，没有逐题即时上传接口。
- 不设业务积分上限，不按同组人数或其他人的表现归一化。例如 43 个有效整秒、首次完成 1 篇、首次答对 2 题，共 113 分。
- 游客、本机未验证记录与待确认同步不冒充已确认积分。无上限不代表有效性永不变化：Quiz 被撤回且没有其他有效正确答案支持时，相应题分失效；后续有效答对可恢复原奖励，但不新增重复奖励。

## 累计积分与榜单期间

个人页面和播放器显示当前有效事件的累计积分。最近 7 日、周、月、年榜只累计选定期间的新增积分，以 Asia/Shanghai 业务时区划分期间；数据库时间使用 UTC。周榜严格按周，周/月可选具体期间，年榜独立保留。

积分相同则并列，展示顺序保持确定性。校区、年级、阅读级别、匿名字段和至少 10 人的隐私门槛保留。已有有效积分但尚未完成书本的用户可以参与符合条件的榜单。

Quiz 撤回或恢复需要重建原奖励发生期间，而不是将旧题分搬到重新提交当天。后续首次答对的新题仍按新的事件时间计分。

## 数据与并发边界

`0010_learning_points` 增加已计分高水位状态、追加式积分事件及有效事件视图，并保留旧规则快照。历史进度按已知更新时间回填，历史题分按已知验证时间回填；没有逐秒历史事件时，不能重建每一分真实发生日期。

当前跨内容版本采用用户和篇目的已计分秒数高水位，版本变化不会重置首次完成或答题奖励，也不会再次奖励同等已计分秒数；这不是跨版本所有收听区间的完整并集。

`0011_learning_score_consistency` 为积分写入和确认读取增加账号级锁，并在 Quiz 有效性变化时追加重建任务。进度、Quiz、导入统一先锁用户再锁业务幂等键；混合导入共享一个事务，不另开嵌套 Quiz 事务。积分和 outbox 同事务提交，失效任务不重置 Worker 已认领的任务。

确认查询在同一账号写入完成后读取新的数据库快照并附 `asOf`；客户端隔离账号状态，拒绝跨账号迟到的 Quiz 回执和较旧的积分回执。0010/0011 回滚有防丢数据拒绝条件；生产回退前需备份并单独演练。

## 接口与数值类型

数据库使用无旧业务上限的 `NUMERIC`，后端以 `BigInt` 精确累加和比较，API 以十进制整数字符串传输积分。前端按字符串格式化，不转为普通 `Number`。

`GET /api/v1/me/learning-score` 返回累计积分、三项拆解、规则版本和 `asOf`；进度与 Quiz 响应可带 `learningScore`。排行配置返回单位规则及 `scoreCap: null`。积分类型和拆解结构是破坏性变更，前后端需按 v2 契约对齐发布；URL 仍为 `/api/v1`。

## 本机验证与上线条件

2026-10-10 客户端 115/115、后端 59/59、类型检查、契约 5/5、密钥扫描及正式/Demo 浏览器回归通过。`test:integration:learning-points` 在隔离 PostgreSQL 与真实本地 HTTP 中验证历史回填、碎片累计、并发去重、首次完成、错题改对、混合导入、撤回恢复、确认读取、版本高水位、超安全整数精度和四种期间榜单；其他排行、导入、进度与迁移 smoke 通过。

服务端能够校验证据结构、版本、时长和区间，但这些校验不证明用户实际听到了音频。生产反作弊、账号热点锁吞吐与规模压测仍需补充。真实微信凭据、合法 HTTPS/API/音源域名、Android/iPhone、双设备、弱网和生产迁移验收未完成；本机通过不改变阶段 0 的 `NO-GO`。
